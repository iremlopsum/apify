# apify 2.1.0 — Non-Breaking Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix six confirmed silent-failure bugs and shrink the published package by 65%, with zero breaking changes to the public API.

**Architecture:** Three independent PRs. PR-1 touches only build config and CI. PR-2 hardens URL construction inside `src/utils/path-params.ts`. PR-3 moves abort-signal ownership from a closure variable into the middleware context, which simultaneously fixes the dedupe cleanup race and the cache-hit-aborts-live-request bug. PR-2 and PR-3 touch disjoint files and can run in parallel.

**Tech Stack:** TypeScript 5.8 (strict, ES2020, `moduleResolution: bundler`), vitest 3.2, zero runtime dependencies, pure ESM.

**Spec:** [`docs/FIXES.md`](../../FIXES.md) — issues #2, #3, #4, #8, #9, #12 and the Package size section.

## Global Constraints

- **Zero runtime dependencies.** Nothing may be added to `dependencies`. Dev-only additions require explicit approval.
- **Never throws.** Every public entry point returns a `Result`. Throwing inside `execute()`'s try block is fine — the existing catch at `src/create-api.ts:527` converts it to a Result. Throwing *outside* that boundary is a bug.
- **Pure ESM.** All internal imports use `.js` extensions even though sources are `.ts` (required by `module: ESNext` + `moduleResolution: bundler`).
- **No breaking changes in this plan.** Public types and runtime behaviour visible to existing consumers must not change, except where a documented bug is being corrected.
- **Tests are excluded from `tsconfig.json`** (`exclude: ["tests"]`) but vitest compiles them directly. Never import from `tests/` inside `src/`.
- **Test commands:** `npm run test:run` (unit), `npm run test:integration` (real `node:http` server), `npm run typecheck`.
- **Commit style:** Conventional Commits (`fix:`, `feat:`, `chore:`, `test:`, `docs:`), matching the existing history.
- **Every commit message ends with:** `Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>`

In `src/utils/path-params.ts`, insert immediately after the `for (const [key, value] of Object.entries(params))` substitution loop closes (currently line 97) and before `let url = ...`:

```ts
  // -------------------------------------------------------------------------
  // Phase 1b: Reject any :token that no param filled in
  // -------------------------------------------------------------------------
  // A mismatch between the path template and the params type would otherwise
  // ship the literal token in the URL AND duplicate the value as a query
  // param — a silently wrong request that looks plausible in a network tab.
  //
  // The pattern mirrors the substitution regex: a colon followed by at least
  // one identifier character. `/time/12:30` is not a match because `30` is
  // preceded by a digit-only segment that never had a token shape... but to
  // be exact we require the colon to start a path segment or follow a slash.
  // -------------------------------------------------------------------------
  const unresolved = resolvedPath.match(/(?<=^|\/):[a-zA-Z_][a-zA-Z0-9_]*/g)
  if (unresolved) {
    throw new TypeError(
      `Unresolved path parameter${unresolved.length > 1 ? 's' : ''} ${unresolved.join(', ')} ` +
      `in path "${path}". Provide ${unresolved.length > 1 ? 'these keys' : 'this key'} in params, ` +
      `or correct the path template.`
    )
  }
```

Note the lookbehind `(?<=^|\/)` — it requires the colon to begin a path segment, so `/time/12:30` does not match. Lookbehind is supported in all runtimes this library targets (Node 18+, all modern browsers, Bun, Deno, Workers).

### Task 5: Normalise the `baseUrl` + `path` join

**Files:**
- Modify: `src/utils/path-params.ts:102`
- Test: `tests/path-params.test.ts`

- Consumes: `buildUrl` as modified by Task 4. Produces: no signature change; only the joined URL differs when `baseUrl` ends with `/`.

**The bug:** `baseUrl: 'https://x.com/'` + `path: '/health'` produces `https://x.com//health`. A trailing slash is the shape you get from `process.env.API_URL` most of the time; some servers 404 on a double slash, and a cross-origin redirect drops the `Authorization` header.

```ts
  // -------------------------------------------------------------------------
  // Phase 2: Join base and path with exactly one separating slash
  // -------------------------------------------------------------------------
  // A trailing slash on baseUrl is the shape process.env.API_URL usually has.
  // Naive concatenation produced '//', which some servers 404 on and which
  // can trigger a cross-origin redirect that drops the Authorization header.
  // An empty baseUrl (same-origin usage) is passed through untouched.

  let url: string

    const tail = resolvedPath.startsWith('/') ? resolvedPath : `/${resolvedPath}`

  }
```

# PR-3 — Cancellation and the abort signal

**Branch:** `fix/cancellation-and-signal`
**Fixes:** #2, #4, #9
**Risk:** Medium — this is the one PR that changes execution ordering. Do the three tasks in order; Task 8 depends on both predecessors.

**The shared root cause:** `effectiveSignal` is computed at `src/create-api.ts:296`, *before* the middleware chain runs at `:502`, and lives in a closure that middleware cannot reach. That single decision causes all three bugs: dedupe registers even when a cache hit means no request happens (#4), cleanup can't tell which controller it owns (#2), and no middleware can implement a timeout (#9).

### Task 6: Make `DedupeTracker.clear()` identity-aware

**Files:**
- Modify: `src/utils/dedupe.ts:97` (`track`), `src/utils/dedupe.ts:161` (`clear`)
- Modify: `src/create-api.ts:298`, `src/create-api.ts:518`
- Modify: `src/graphql.ts:103`, `src/graphql.ts:183`
- Test: `tests/dedupe.test.ts`

**Interfaces:**
- Consumes: nothing from earlier tasks.
- Produces:
  - `track(key: string, externalSignal?: AbortSignal): { signal: AbortSignal; controller: AbortController }` — **return shape changes** from a bare `AbortSignal`.
  - `clear(key: string, controller?: AbortController): void` — deletes only if the stored controller is identical; omitting `controller` preserves the old unconditional behaviour.
  - Task 8 consumes both.

**The bug:** when request B supersedes A, A settles *after* B registered, so A's cleanup deletes **B's** entry. Dedupe then silently stops working from the second cancellation onward.

- [ ] **Step 1: Write the failing test**

- [ ] **Step 8: Add the end-to-end regression test**

Create `tests/dedupe-race.test.ts`:

```ts
import { describe, it, expect, vi, beforeEach, afterEach } from 'vitest'
import { createApi } from '../src/create-api.js'
import { Request } from '../src/request.js'

function deferredFetch() {
  const calls: { resolve: () => void; aborted: () => boolean }[] = []
  const fn = vi.fn((_u: string, init: RequestInit) => new Promise<Response>((res, rej) => {
    const signal = init.signal as AbortSignal
    signal.addEventListener('abort', () => rej(new DOMException('Aborted', 'AbortError')))
    calls.push({
      resolve: () => res(new Response('{"ok":1}', { status: 200 })),
      aborted: () => signal.aborted,
    })
  }))
```

### Task 8: Register dedupe inside `core`, not before the middleware chain

**Files:**
- Modify: `src/create-api.ts:296-299` (remove early registration), `:318` (register inside core), `:514` (cleanup)
- Modify: `src/graphql.ts:101-104`, `:106`, `:182`
- Test: `tests/dedupe.test.ts`, new `tests/dedupe-cache.test.ts`

**Interfaces:**
- Consumes: Task 6's `track()`/`clear()` shapes and Task 7's `ctx.request.signal`.
- Produces: final ordering — dedupe registers only when a request is genuinely about to be sent.

**The bug:** a short-circuiting middleware (a cache hit) currently still aborts a live in-flight request, because `track()` ran before the chain. Verified: composing `dedupe: true` with `cacheMiddleware` is broken today.

## Deferred: type-level path constraint

Your suggestion — derive the expected `path` type from whether `baseUrl` ends
with `/` — was prototyped and **works**. Using an intersection (not a union) to
keep `TPath` inferrable:

```ts
type CheckPath<TBase extends string, TPath extends string> =
  TBase extends `${string}/`
    ? TPath extends `/${string}` ? "ERROR: baseUrl ends with '/' — drop the leading '/'" : TPath
    : TPath extends `/${string}` ? TPath : "ERROR: path must start with '/'"

declare function mkApi<TBase extends string, TPath extends string>(
  baseUrl: TBase, path: TPath & CheckPath<TBase, TPath>
): void
```

Verified results: `('https://x.com', 'health')`, `('https://x.com/', '/health')`
and `(envBase, 'health')` all error; the three correct combinations compile.

**Why it is not in PR-2:**

1. **Architecture fights it.** `Request` instances are constructed independently
   of `createApi`, so `path` is fixed before `baseUrl` is known. Enforcement has
   to happen at `createApi` across the whole `requests` record, and the error
   then points at the record rather than the offending `Request`.
2. **The error message is `not assignable to 'never'`.** The branded string does
   not surface — a known TypeScript limitation.
3. **It does not help the common case.** When `baseUrl` comes from
   `process.env.API_URL` its type is `string`, not a literal, so the `//` branch
   is unreachable and the constraint degrades to "path must start with `/`".

Runtime normalisation (Task 5) covers every case including the env-var one. The
type constraint is worth revisiting as a feature if `Request` ever gains a
path-template generic — see [FEATURES.md #1](../../FEATURES.md#1-infer-path-params-from-the-path-template),
which would make it natural.
